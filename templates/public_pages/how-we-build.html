How we build

The Hermes method

How we put AI into a business process and keep it working.

Start with the process, not the technology

We begin with one real process where money leaks or time disappears: an invoice check, a monthly pack, a stack of paperwork. We build for that, prove it pays, then move to the next. Each step is added after a real case shows it is needed.

One home for the data

  • A cloud data warehouse holds the shared company data: invoices, deliveries, ledgers, claims. Everyone, human or AI, works from the same numbers.
  • A lightweight local analytics database handles fast, private work on files that should not leave your own equipment.

The right model for each job

No single AI is best at everything, and none of them is the cheapest for everything either. We are not tied to one provider. We pick the best model for each task and swap it when something better comes along.

JobType of modelExample and why
Searching and researchA search model that cites its sourcesPerplexity. When we need a current fact, such as a market price, a regulation or a supplier, it gives an answer with links we can check.
Hard reasoning and reviewA top-tier reasoning modelClaude. It reads contracts, checks invoices and challenges other models' work. Worth paying more for when a mistake is expensive.
Routine sorting and checkingA small, fast, cheap modelA lightweight Claude model. It triages emails, classifies documents and does repetitive checks at a fraction of the cost.
ImagesAn image generation modelSeedream. We used it to draw the characters for a children's game, because it holds a consistent style across hundreds of frames.
Meetings and voiceA speech model that runs on your own equipmentWhisper. Audio is turned into text without leaving the building, which matters for boards and legal discussions.

One model does the work, another checks it

For anything that matters, one model produces the answer and a different one reviews it. The reviewer is set up to find problems, not to agree. It catches mistakes a single model will miss, and it is cheap compared with a wrong figure reaching a board or a supplier.

Run on a schedule, with rules in one place

  • Tasks run on a timetable, hourly, daily or weekly, each owning one job and one deadline.
  • All the rules live in a single rulebook that every task reads at the start of each run. To change how the system behaves, you change the rulebook, not a dozen separate instructions.
  • Every run leaves a written record, so anyone can pick up exactly where the last one stopped.

People approve the money

AI does the reading, checking and drafting. A person approves anything that spends money, goes to an outside party for the first time, or cannot be undone. Safety stops are built in: if something looks wrong, the system sends nothing and says why.

Your data stays yours

Sensitive information stays on systems you control, behind proper access controls. Because we are not tied to one AI provider, we can choose where each job runs, including on your own equipment.
